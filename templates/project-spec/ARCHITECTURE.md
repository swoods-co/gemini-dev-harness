# System Architecture & Technical Design\n\n## 1. System Overview\nHigh-level overview of the application flow, data pipeline, and system boundaries.\n\n```mermaid\nflowchart LR\n    User[Client Browser] <--> CDN[Netlify Edge CDN]\n    CDN <--> App[Frontend App]\n    App <--> API[Backend API / Gateway]\n    App <--> ThirdParty[Third-Party Services]\n```\n\n---\n\n## 2. Component Hierarchy & Data Flow\n- **Data Fetching Pattern**:\n  - Initial load data caching and prefetching.\n  - Client-side updates, optimistic mutations, and cache invalidation strategies.\n- **State Boundaries**:\n  - Global vs. local state separation.\n  - URL as state (filter parameters, search queries, pagination state stored in query params).\n\n---\n\n## 2.1 Backend Contract & Mock Data Architecture (Contract-First MVP)\nTo allow rapid frontend prototyping and testing before backend endpoints are live:\n- **Contract Definition**: TypeScript interfaces and Zod validation schemas are generated directly from backend OpenAPI/Swagger specs, GraphQL schemas, or payload definitions in `src/types/` and `src/services/schemas/`.\n- **Mock Layer (`VITE_USE_MOCKS`)**:\n  - During MVP development, the application serves realistic dummy data with realistic network latency simulation.\n  - Handled via Mock Service Worker (MSW) or API adapter pattern (`src/services/api/mock/`).\n- **Zero-Rewrite Production Switch**:\n  - Switching from MVP dummy data to production requires only changing `.env`:\n    ```env\n    VITE_USE_MOCKS=false\n    VITE_API_BASE_URL=https://api.yourcompany.com\n    ```\n  - All UI components, state hooks, and query clients remain 100% untouched.\n\n---\n\n## 3. Error Handling & Resilience\n- **Error Boundaries**: Root-level and route-level error boundaries with user-friendly fallback screens.\n- **Network Resilience**: Exponential backoff retry on transient API network errors.\n- **Monitoring & Observability**: [e.g., Sentry / Datadog / OpenTelemetry] integration points.\n\n---\n\n## 4.
